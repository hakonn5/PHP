# Каталог учебных материалов (Study Hub)

## Описание индивидуального проекта
Данный проект представляет собой полноценное веб-приложение "Каталог учебных материалов" (Study Hub), разработанное в рамках курса по программированию на PHP. 
Цель проекта — продемонстрировать навыки создания веб-приложений с использованием архитектурного паттерна MVC, нативного языка PHP (без сторонних фреймворков), взаимодействия с базой данных PostgreSQL через PDO и контейнеризации приложения с помощью Docker.

Проект спроектирован с упором на чистоту кода, безопасность (защита от SQL-инъекций и XSS), использование современных возможностей PHP 8.x, а также на создание адаптивного интерфейса с использованием Bootstrap 5.

### Инструкции по запуску проекта

Для запуска проекта на вашем локальном компьютере потребуется установленный Docker и Docker Compose.

1. **Клонируйте репозиторий или перейдите в папку с проектом:**
   ```bash
   cd study_hub
   ```

2. **Запустите Docker Compose:**
   Команда соберет образ веб-сервера и поднимет контейнеры приложения и базы данных.
   ```bash
   docker-compose up -d --build
   ```

3. **Откройте приложение в браузере:**
   Перейдите по адресу: [http://localhost:8000](http://localhost:8000)

4. **Доступ к панели администратора:**
   При первой инициализации базы данных автоматически создается аккаунт администратора:
   - **Email:** `admin@example.com`
   - **Пароль:** `admin123`

5. **Остановка проекта:**
   ```bash
   docker-compose down
   ```

*(Примечание: папка `logs/` используется для сохранения локальных логов, таких как имитация отправки email для восстановления пароля. Убедитесь, что Docker имеет права на чтение/запись в эту директорию.)*

### Функциональные возможности

**Общедоступные функции (Public Area):**
- Просмотр списка последних добавленных учебных материалов на главной странице.
- Поиск материалов по названию и описанию (`ILIKE` для регистронезависимого поиска).
- Фильтрация материалов по категориям.
- Регистрация и авторизация пользователей.
- Восстановление пароля (генерация токена и запись ссылки для сброса в лог-файл `logs/emails.log`).

**Функции авторизованных пользователей:**
- Добавление новых учебных материалов в каталог с указанием названия, категории, формата (PDF, Video, Article), сложности и детального описания.

**Функции администратора (Admin Panel):**
- Доступ защищен специальным Middleware, проверяющим роль `admin`.
- **Управление пользователями:** Просмотр списка всех зарегистрированных пользователей, возможность назначения любого пользователя администратором.
- **Управление материалами (CRUD):** Просмотр всех материалов в виде таблицы, редактирование любых записей и их удаление.
- **Управление категориями:** Добавление новых категорий, просмотр и удаление существующих.

**Технические и архитектурные решения:**
- Архитектура **Упрощенный MVC** (Models, Views, Controllers) с единой точкой входа `public/index.php`.
- Взаимодействие с базой данных PostgreSQL осуществляется исключительно через **PDO** с использованием подготовленных запросов (Prepared Statements).
- Хеширование паролей через алгоритм `Bcrypt` (`password_hash()`).
- Защита от **XSS** посредством безопасного вывода данных (`htmlspecialchars()`).
- Защита от **фиксации сессий** (`session_regenerate_id(true)`).
- Информативные `flash`-сообщения (уведомления об ошибках и успехах) через сессии.

### Сценарии взаимодействия пользователей с приложением

#### Сценарий 1: Гость ищет нужный материал
1. Пользователь заходит на главную страницу и видит блок "Последние добавленные материалы".
2. Гость переходит на вкладку **"Search Resources"**.
3. Вводит ключевое слово в строку поиска и выбирает нужную категорию из выпадающего списка.
4. Нажимает "Search" и видит карточки подходящих материалов с указанием авторов, форматов и уровня сложности.

#### Сценарий 2: Регистрация нового пользователя и добавление материала
1. Гость переходит на страницу **"Register"**, вводит имя пользователя, email и пароль (с подтверждением).
2. После успешной регистрации (с валидацией совпадения паролей на клиенте и сервере) пользователь перенаправляется на страницу **"Login"**, где входит в аккаунт.
3. В навигационном меню появляется кнопка **"+ Add Resource"**.
4. Пользователь заполняет форму добавления ресурса. В случае ошибок заполнения (например, не выбран формат), JS и PHP валидация блокирует отправку и возвращает понятное сообщение об ошибке.
5. При корректном заполнении материал сохраняется в базу и становится доступным в общем каталоге поиска.

#### Сценарий 3: Имитация восстановления пароля
1. Пользователь забыл пароль и нажимает на ссылку **"Forgot Password?"** на странице входа.
2. Вводит свой email и нажимает "Send Reset Link".
3. Система генерирует уникальный токен и записывает ссылку для восстановления в лог-файл (эмулируя отправку письма).
4. Разработчик/пользователь открывает `logs/emails.log`, находит ссылку, по которой (в рамках доработки) можно было бы восстановить пароль.

#### Сценарий 4: Администрирование портала
1. Пользователь авторизуется под учетной записью с ролью `admin`.
2. В навигационном меню появляется выпадающий список **"Admin Panel"**.
3. Администратор переходит в раздел **"Users"** и нажимает "Make Admin" напротив рядового пользователя, расширяя его права.
4. В разделе **"Categories"** администратор добавляет новую категорию для учебных материалов или удаляет старую.
5. В разделе **"Resources"** администратор просматривает все записи в виде таблицы. Найдя материал с опечаткой, нажимает "Edit" (открывается модальное окно), исправляет текст и сохраняет изменения, либо полностью удаляет неактуальную запись.

### Структура базы данных

База данных работает под управлением PostgreSQL. Ниже представлены основные таблицы и их связи:

#### 1. Таблица `users`
Хранит информацию о зарегистрированных пользователях приложения.
- `id` (SERIAL PRIMARY KEY) — Уникальный идентификатор.
- `username` (VARCHAR) — Имя пользователя.
- `email` (VARCHAR, UNIQUE) — Адрес электронной почты (используется для входа).
- `password_hash` (VARCHAR) — Захешированный пароль (Bcrypt).
- `role` (VARCHAR) — Роль пользователя (ограничение CHECK: `'user'` или `'admin'`). По умолчанию `'user'`.
- `reset_token` (VARCHAR) — Токен для сброса пароля (опционально).
- `created_at` (TIMESTAMP) — Дата и время регистрации (устанавливается автоматически).

#### 2. Таблица `categories`
Справочник категорий учебных материалов (Programming, Mathematics и т.д.).
- `id` (SERIAL PRIMARY KEY) — Уникальный идентификатор.
- `name` (VARCHAR, UNIQUE) — Название категории.

#### 3. Таблица `resources`
Содержит учебные материалы, добавленные пользователями.
- `id` (SERIAL PRIMARY KEY) — Уникальный идентификатор ресурса.
- `title` (VARCHAR) — Название материала.
- `category_id` (INTEGER, FOREIGN KEY) — Ссылка на `categories(id)`. Правило `ON DELETE SET NULL` (при удалении категории материал остается, но без привязки).
- `format` (VARCHAR) — Формат материала. Строгое ограничение CHECK: `'pdf'`, `'video'`, `'article'`.
- `difficulty` (VARCHAR) — Уровень сложности. Строгое ограничение CHECK: `'easy'`, `'medium'`, `'hard'`.
- `description` (TEXT) — Подробное описание.
- `created_by` (INTEGER, FOREIGN KEY) — Ссылка на автора `users(id)`. Правило `ON DELETE CASCADE` (при удалении пользователя удаляются все его материалы).
- `created_at` (TIMESTAMP) — Дата и время добавления.

**Основные связи (Relations):**
- Один ко многим (1:M): Одна категория -> Множество ресурсов.
- Один ко многим (1:M): Один пользователь -> Множество созданных ресурсов.
